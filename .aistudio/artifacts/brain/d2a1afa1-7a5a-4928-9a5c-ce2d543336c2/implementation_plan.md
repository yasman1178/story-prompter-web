# خطة المعالجة الشاملة: نظام ضغط الصور الفوري (WebP 720x1280) وحل مشاكل تجمد وانهيار الاستوديو

تحليل شامل لأسباب توقف المتصفح وتجمده (Aw, Snap! / Memory Exhaustion) وتطبيق معمارية خفيفة وسريعة تقوم بضغط الصور فور رفعها إلى WebP بدقة 720x1280 وجودة 82%، مع ضغط الصور المحملة حالياً في المشروع فوراً، وإصلاح تسريبات الذاكرة في المعاينة والتصدير.

---

## User Review & Critical Decisions

> [!IMPORTANT]
> تم تأكيد القرارات التصميمية والتقنية التالية في مرحلة الاستيضاح مع المستخدم:

- **Confirmed Decision 1**: اعتماد دقة 720x1280 وجودة 82% بصيغة WebP الحديثة مع الحفاظ على شفافية طبقات العناصر الأمامية (FG Cutouts Alpha Channel)، مما يوفر أكثر من 90% من استهلاك الذاكرة العشوائية ومساحة التخزين في IndexedDB.
- **Confirmed Decision 2**: ضغط وتحديث الصور الحالية المخزنة في المشروع فوراً عبر أداة ترقية وضغط مدمجة في واجهة المشروع ونافذة المطابقة، لتحرير الذاكرة المخزنة مسبقاً وإنعاش أداء المتصفح على الفور.
- **Root Cause Analysis (تحليل أسباب التجمد الأخرى)**:
  1. **التخزين المتزامن بدون تحجيم**: محاولة حفظ 30 إلى 50 صورة خام بدقة 4K/2K دفعة واحدة عبر `Promise.all` تسبب قفزة ذاكرة (RAM Spike) تتجاوز 1.5 جيجابايت في الثانية الأولى.
  2. **تسريب كائنات URL و ImageBitmap**: عدم استدعاء `URL.revokeObjectURL` أو الاحتفاظ بنسخ متعددة من `ImageBitmap` في الذاكرة دون إغلاقها (`bitmap.close()`).
  3. **حصار الـ Main Thread أثناء المعاينة والتصدير**: استمرار عمليات الرسم والرندر دون منح المتصفح فرصة للتنفس (GC Micro-Yielding) كل بضعة إطارات مما يجعل المتصفح يظن أن الصفحة علقت فيقوم بإنهائها.

## 1. Overview & Core Concept

- **What It Does**:
  - **محول ومحسن فوري للصور (Client-Side Immediate Image Optimizer)**: بمجرد اختيار المستخدم لملفات الصور (سواء عبر السحب والإفلات، رفع المجلد، استبدال صورة مفردة، أو رفع العناصر المفرغة)، يتم تمرير الصورة فوراً عبر دالة تحجيم وضغط ترسمها على Canvas بأقصى أبعاد 720x1280 مع الحفاظ على النسبة الباعية، ثم تحويلها إلى `image/webp` بجودة 0.82 قبل حفظها في IndexedDB.
  - **أداة ضغط الصور الحالية (Project Legacy Image Compressor)**: زر سريع ومؤشر تقدم ينبثق للمستخدم لفحص وضغط الصور الموجودة بالفعل في المشروع، لتخفيض مساحة قاعدة البيانات المحلية من مئات الميجابايتات إلى بضعة ميجابايتات خفيفة.
  - **تنظيم تدفق الذاكرة التتابعي (Throttled Concurrency Pipeline)**: معالجة رفع الصور بشكل متسلسل أو بدفعات صغيرة (Concurrency: 2) لمنع التشنج المفاجئ للمتصفح.
  - **تحسين دورة حياة الصور في الكانفس والرندر**: التأكد من إغلاق الـ Bitmaps وإلغاء الـ Object URLs القديمة عند تبديل المشاهد، مع فترات سماح (micro-yield) كل 5 إطارات أثناء تصدير الفيديو.

- **Target Audience / Persona**:
  - صانع محتوى الشورتس والأنمي الذي يرفع عشرات الصور ذات الدقة العالية (فوق 2K و 4K) ويريد تشغيل المعاينة والرندر بسلاسة تامة على متصفحات الهواتف والحواسيب المتوسطة دون أي انهيار.

- **Key Value**:
  - القضاء التام على أخطاء الذاكرة "Aw, Snap!" وتجمد الصفحة.
  - تسريع ملحوظ في سرعة فتح الاستوديو وتقليب المشاهد وتصدير الفيديو بنسبة تتجاوز 70%.

## 2. User Experience & Visual Design

- **Key User Flows**:
  1. **عند رفع الصور (مجلد أو صور فردية)**:
     - يظهر مؤشر تقدم خفيف وسريع: "جارٍ ضغط وتحسين الصور إلى WebP (720x1280)... [12/35]".
     - يتم حفظ الصور الناتجة فوراً بحجم خفيف جداً (بين 50 و 120 كيلوبايت للصورة بدلاً من 5 ميجابايت).
  2. **زر تحسين وضغط الصور الحالية (Clean & Compress Current Images)**:
     - يظهر في شريط أدوات تبويب المشاهد (/project) ونافذة المطابقة زر أنيق: "ضغط وتحرير ذاكرة صور المشروع".
     - بنقرة واحدة، يظهر شريط تقدم سلس يقوم بقراءة الصور الحالية في IndexedDB وضغطها إلى WebP وحفظها وتحديث حجم المشروع، مع إشعار نجاح فوري: "تم ضغط 32 صورة بنجاح وتوفير 88% من الذاكرة!".
  3. **معاينة وتصدير الفيديو (/video و /hook)**:
     - تشغيل المعاينة بسلاسة تامة بمعدل 30-60 إطار في الثانية دون تقطيع.
     - التصدير يتم دون أن تتجمد الواجهة، مع تحديث نسبة الإنجاز في الوقت الفعلي.

- **Visual Identity & Theme**:
  - الحفاظ على هوية الاستوديو الداكنة ذات التباين النظيف (Dark Slate `#080B10` مع أسطح `#161F30` وحدود هادئة `#334155`).
  - أزرار التحسين بألوان مميزة خالية من التعقيد، وأشرطة تقدم دقيقة برقم العداد التناسبي (`font-mono tabular-nums`).
  - الالتزام التام بقواعد `frontend-design`: نصوص واضحة غير مغلفة في كبسولات عشوائية، أزرار ذات أهداف نقر مريحة (44px)، وحركة سلسة دون استهلاك لموارد المعالج.

## 3. Key Product Decisions & Trade-Offs

- **Decision 1: Client-Side WebP Compression vs Server-Side Processing**:
  - *Chosen Approach*: الضغط يتم محلياً على جهاز المستخدم عبر واجهات المتصفح القياسية (`createImageBitmap` + `OffscreenCanvas` / `HTMLCanvasElement` + `toBlob('image/webp', 0.82)`).
  - *Why*: لا يتطلب رفع مئات الميجابايتات إلى الخادم عبر الشبكة، ويعمل فوراً حتى لو كان اتصال الإنترنت بطيئاً، ولا يستهلك باندويث الخادم.
  - *Alternatives Considered*: رفع الصور ومعالجتها بسيرفر node-sharp؛ رُفضت لأن رفع 200 ميجابايت عبر اتصال هاتف بطيء سيستغرق دقائق طويلة وسيفشل في حالات انقطاع الاتصال.

- **Decision 2: Max Dimension 720x1280 (Vertical Shorts Standard)**:
  - *Chosen Approach*: تحجيم الصورة بحيث لا يتجاوز عرضها 720px ولا يتجاوز ارتفاعها 1280px مع الحفاظ التام على أبعاد الصورة الأصلية (Aspect Ratio).
  - *Why*: هو المعيار الدقيق لفيديوهات الشورتس العمودية (9:16) المستخدم في كانفس الرندر، مما يمنع الكانفس من إهدار الذاكرة في تصغير صور 4K في كل إطار رندر 30 مرة بالثانية.
  - *Alternatives Considered*: ضغط بجودة 1080x1920؛ المستخدم اختار 720x1280 صراحة كخيار موصى به لأعلى خفة وتوفير للذاكرة ومنع الانهيار.

- **Decision 3: Preserving Transparency for Cutouts (PNG/WebP Alpha)**:
  - *Chosen Approach*: فحص نوع الصورة واسمها؛ إذا كانت صورة عنصر مفرغ (`_fg` أو تحتوي على شفافية)، يتم الحفاظ على قناة الشفافية Alpha عبر WebP Lossless/Alpha أو PNG محسّن.

## 4. Technical Architecture & Data Strategy

```
┌────────────────────────────────────────────────────────────────────────┐
│                        User Upload Interfaces                          │
│   (Folder Drop / Matcher Modal / ShotCard Single / Existing Project)   │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ File / Blob
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│                image-optimizer.ts (Client-Side Pipeline)               │
│                                                                        │
│   1. createImageBitmap / HTMLImageElement decode                       │
│   2. Aspect-ratio preserving resize (Max: 720w x 1280h)                │
│   3. Canvas draw & toBlob("image/webp", 0.82)                          │
│   4. Sequential Throttling (Concurrency: 2)                            │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ Compressed WebP Blob (~60KB)
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│                        IndexedDB Storage (idb)                         │
│             Tiny footprint (~2MB total for 30 shots project)           │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ On-Demand Stream
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│            Studio Timeline, Canvas Preview & Video Exporter            │
│   - LRU / Sliding Window Cache                                         │
│   - bitmap.close() on shot transition                                  │
│   - GC Micro-Yielding (every 5 frames during video export)             │
│   - Audio buffer lazy loading with non-blocking decode                 │
└────────────────────────────────────────────────────────────────────────┘
```
