# خطة حل مشاكل توليد الأصوات والرندر وتفعيل الاختيار الحر لنطاق مشاهد الشورت

خطة معمارية وهندسية شاملة لإصلاح وتطوير استوديو حكايات الشورتس: تمكين الاختيار الحر لنطاق المشاهد (من المشهد X إلى المشهد Y) في المعاينة والرندر، وحل أعطال توليد الأصوات الدفعية عبر Edge-TTS، وضمان تصدير فيديو MP4 عالي التوافق مع بديل WebM السريع.

> [!IMPORTANT]
> **القرارات المؤكدة من مرحلة الأسئلة والاستيضاح:**
> - **تحديد نطاق المشاهد:** إتاحة اختيار رقم مشهد البداية والنهاية بحرية كاملة مع أزرار اختصار سريعة للأجزاء المتتالية (مثل: الجزء الأول 1-5، الجزء الثاني 6-10، إلخ) لحساب مدة الشورت المناسبة بدقة (30-60 ثانية).
> - **توليد الأصوات الدفعية:** توليد جميع أصوات المشاهد دفعة واحدة مع نظام محاولات ذكي (Retry Mechanism)، وتأخير منتظم يمنع حظر الاتصال، وتخزين موثوق في قاعدة البيانات المحلية (IndexedDB).
> - **صيغة تصدير الفيديو:** اعتماد صيغة MP4 (H.264 + AAC) المتوافقة مع يوتيوب شورتس وتيك توك، مع تحويل تلقائي انسيابي لـ WebM في حال عدم توفر برنامج التشفير العتادي في المتصفح لمنع توقف الرندر نهائياً.

---

## 1. نظرة عامة والهدف الأساسي (Overview & Core Concept)

- **المشكلة الحالية:** 
  1. عند محاولة تصدير الفيديو، كان المحرك يُجبر على رندر كامل المشروع (أكثر من 30 مشهداً بمدة تتجاوز دقيقتين ونصف)، مما يسبب استهلاكاً هائلاً للذاكرة وتعليق المتصفح أو فشل الرندر، كما يتنافى مع طبيعة فيديوهات "الشورتس" العمودية (15 إلى 60 ثانية).
  2. واجه توليد الصوت الجماعي (Batch TTS) انقطاعات متفرقة بسبب طول زمن الاتصال وقيود خادم الصوت عند إرسال طلبات متتالية سريعة بدون إدارة زمنية مرنة.
  3. غياب إمكانية تقسيم القصة الواحدة إلى سلسلة شورتس (أجزاء مستقلة) من داخل واجهة المعاينة والرندر.
- **الحل المقدم:**
  1. **نظام التحكم في نطاق الشورت (Custom Scene Range Selector):** سلايدر ومحدد رقمي سلس يسمح للمخرج باختيار "من مشهد كذا إلى مشهد كذا" مع شريط توقيت ديناميكي يحسب مدة الشورت بالثواني فوراً.
  2. **محرك تصدير معزول النطاق (Range-Aware Video & Audio Engine):** توليف وتصدير المشاهد المحددة فقط وتصفير التوقيت النسبي لها، ودمج الأصوات والمؤثرات المتزامنة وموسيقى الخلفية مع الـ Ducking المحسوب بدقة لنطاق الشورت.
  3. **استقرار محرك Edge-TTS:** تحديث عميل توليد الصوت بإدارة متقدمة للمحاولات المتكررة (Exponential Backoff)، وفك ترميز الصوت الموثوق داخل AudioContext، وتأكيد عمل نقطة النهاية `/api/tts` بنجاح دائم.

## 2. تجربة المستخدم والتصميم البصري (UX & Visual Design)

### مسار الاستخدام (User Flow)
1. **صفحة الفيديو والمعاينة (`/video`):**
   - ظهور لوحة تحكم علوية تفاعلية مخصصة تحت الكانفس: "نطاق الشورت (Shorts Clip Range)".
   - مدخلان رقميان واضحان: `من مشهد [ X ]` إلى `مشهد [ Y ]`، مع سلايدر ثنائي المقابض، وشارة تعرض التوقيت الكلي للشورت (مثلاً: `42.5 ثانية · 5 مشاهد`).
   - أزرار ذكية للأجزاء السريعة: `[الجزء 1: المشاهد 1-6]`, `[الجزء 2: المشاهد 7-12]`, `[كامل المشروع]`.
   - مشغل الكانفس وشريط التمرير (Scrubber) يركزان فقط على المشاهد المختارة أو المشروع كاملاً بضغطة زر.
   - زر التصدير يُظهر بوضوح: `تصدير شورت المشاهد (X إلى Y) - MP4`.

2. **صفحة التسجيل والصوتيات (`/record`):**
   - ترقية واجهة توليد الأصوات لتشمل شريط تقدم تفصيلي يعرض المشهد الحالي، عدد المشاهد المكتملة، وزر إعادة محاولة المشاهد التي تعثرت دون الحاجة لإعادة توليد الكل من الصفر.
   - التحقق الفوري من جاهزية الصوت وربطه بالمشاهد وتحديث أزمنة المشاهد تلقائياً.

3. **الهوية البصرية:**
   - الحفاظ على المظهر السينمائي للأنمي والمانهوا المظلمة (Dark Slate `#080B10` مع خطوط السيان البراقة `#00E5FF`).
   - اعتماد الأرقام الجدولية `tabular-nums` في جميع حقول التوقيت والمشاهد لمنع اهتزاز الواجهة.
   - أزرار واضحة وبسيطة بلغة عربية وظيفية دقيقة.

## 3. القرارات التقنية والمفاضلات (Key Product Decisions)

- **القرار الأول: معالجة نطاق المشاهد في محرك التصدير (Range Slice vs New Sub-Project)**
  - *الخيار المعتمد:* دالة تصنيع مشروع فرعي مقتطع بنطاق زمني مصفّر (`sliceProjectRange(project, startShot, endShot)`).
  - *السبب:* الحفاظ على بنية البيانات الأصلية للمشروع في مخزن Zustand كما هي دون تدمير المشاهد الأخرى، مع تمرير نسخة نظيفة إلى محرك الرندر (`drawFrame` و `buildMixedAudio`) تبدأ من زمن 0.0 ثانية حتى زمن نهاية النطاق، مما يضمن خروج فيديو MP4 متناسق 100%.

- **القرار الثاني: معمارية رندر الفيديو (WebCodecs مع Fallback آمن لـ MediaRecorder)**
  - *الخيار المعتمد:* محرك هجين سريع؛ يستعين بـ WebCodecs + mp4-muxer أولاً لرندر فائق السرعة خارج الوقت الحقيقي (Offline Rendering)، وإذا لم يدعم المتصفح ترميز H.264/AAC أو حدث خطأ، ينتقل تلقائياً لـ MediaRecorder لضمان عدم توقف المستخدم أبداً.
  - *السبب:* WebCodecs ينتج ملفات MP4 نقية وخفيفة بدقة 1080×1920 أو 720×1280 دون فقدان في الإطارات، بينما MediaRecorder يضمن التوافقية الشاملة لكافة الأجهزة.

- **القرار الثالث: استقرار توليد الأصوات (Batch Edge-TTS Resiliency)**
  - *الخيار المعتمد:* إضافة آلية إعادة المحاولة (Up to 3 retries) مع فحص سلامة Buffer الصوت وتحديث وقت المشهد فور الانتهاء، مع فاصل زمني مقنن (Pacing Delay) لتفادي قطع الاتصال.

## 4. البنية المعمارية واستراتيجية البيانات (Technical Architecture)

### مخطط تدفق النظام (Architecture Diagram)

```
┌────────────────────────────────────────────────────────────────────────┐
│                        Zustand Studio Store                            │
│  - project (StoryProject)                                              │
│  - selectedRange: { startShot: number, endShot: number }               │
│  - shotAudioAssignments (IndexedDB Asset IDs)                          │
└───────────────────┬────────────────────────────────┬───────────────────┘
                    │                                │
         [Preview & Scrubber]               [Batch TTS Engine]
                    │                                │
                    ▼                                ▼
┌──────────────────────────────────────┐  ┌──────────────────────────────┐
│       Interactive Canvas View        │  │     Edge-TTS Batch API       │
│  - Scrubber bounded to active range  │  │  - Paced requests            │
│  - Active shot preview & DND overlay │  │  - Retry backoff on timeout  │
│  - Real-time SFX & Voice preview     │  │  - Stores audio in IDB       │
└───────────────────┬──────────────────┘  └──────────────────────────────┘
                    │
                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│                 Range Export Engine (video-export.ts)                  │
│                                                                        │
│  1. sliceProjectRange(project, start, end)                             │
│     ├── Remap start/end times starting from 0.0s                       │
│     └── Filter relevant shots, SFX cues, and duration                  │
│                                                                        │
│  2. Audio Synthesis (buildMixedAudio)                                  │
│     ├── Decode shot audio buffers via OfflineAudioContext              │
│     ├── Duck BGM under voiceover narration                             │
│     └── Trigger acoustic SFX at exact trigger offsets                  │
│                                                                        │
│  3. Video Rendering & Multiplexing                                     │
│     ├── WebCodecs H.264 + mp4-muxer AAC (Fast Offline Export)          │
│     └── Seamless Fallback: MediaRecorder (WebM/MP4)                    │
└────────────────────────────────────────────────────────────────────────┘
```

### خطة التعديل على الملفات (Target Implementation Sequence)
1. **`src/lib/types.ts` & `src/lib/timeline.ts`:**
   - إضافة واجهة `ShotRange` ودالة مساعدة لاقتصاص وإعادة حساب التوقيت لنطاق المشاهد المحدد.
2. **`src/lib/video-export.ts`:**
   - تحديث دالة `exportStoryVideo` لدعم معامل `shotRange: { start: number, end: number }`.
   - إصلاح معالجة فك تشفير الصوتيات MP3 في `OfflineAudioContext` وإدارة الـ Fallback لتفادي أي خطأ صامت أو توقف.
3. **`src/app/(studio)/video/page.tsx`:**
   - بناء مكون اختيار نطاق المشاهد التفاعلي (من مشهد X إلى مشهد Y) مع أزرار الأجزاء السريعة وحساب مدة الشورت.
   - ربط المعاينة وشريط التمرير وزر التصدير بالنطاق المختار.
4. **`src/app/(studio)/record/page.tsx` & `src/lib/tts-client.ts`:**
   - تحسين خوارزمية توليد الأصوات الجماعية مع مؤشرات التقدم وإعادة المحاولة التلقائية.
5. **الفحص والتحقق (`compile_applet` & `lint_applet`):**
   - فحص سلامة البناء واختبار توليد الصوت ورندر الفيديو للنطاقات المختلفة.
