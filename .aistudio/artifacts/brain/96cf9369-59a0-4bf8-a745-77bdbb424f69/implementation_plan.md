# خطة المعالجة الشاملة لمطابقة الصور الذكية وفصل الطبقات البصرية

معالجة جذرية لخلل مطابقة الصور الناتج عن تداخل أرقام الإصدارات (`v24` و `v26`) وأرقام الفصول (`ch171819`) مع أرقام المشاهد، مما تسبب في ظهور 9 مشاهد بدون خلفيات وارتباط غير دقيق في لقطة الشاشة.

---

## User Review & Critical Decisions

> [!IMPORTANT]
> تم تأكيد الخيارات الرئيسية مع المستخدم عبر جلسة الاستيضاح التفاعلية:

- **Confirmed Decision 1**: استخراج رقم المشهد يعتمد بصرامة على البادئات المعيارية مثل `shot_02` أو `scene_02` وتجاهل تام لأرقام الإصدارات اللاحقة مثل `v24` أو `v26` أو أرقام الفصول `ch171819`.
- **Confirmed Decision 2**: العناصر الأمامية المفرغة (FG) لم تُرفع بعد في هذا المشروع؛ سيتم إبقاء مساراتها المفرغة جاهزة دون أن تعطل أو تشوش على مطابقة الخلفيات الأساسية.
- **Confirmed Decision 3**: معالجة المشاهد الـ 9 المتبقية عبر فرز ذكي يتعرف على أرقام المشاهد الحقيقية تلقائياً لسد النواقص مع توفير زر تصحيح وتعبئة تسلسلية ذكية في حال نقص بعض المشاهد من الحزمة.

## 1. Overview & Core Concept

### ما الذي سنقوم بإصلاحه وتطويره؟
1. **دقة استخراج رقم المشهد (`extractShotNumberFromFilename`)**:
   - استبدال التعبير النمطي الحالي الذي كان يلتقط أي رقم عام (مثل `24` من `v24` أو `17` من `ch171819`) بدالة تحليل متخصصة تستخرج رقم المشهد الحقيقي من البادئة: `shot_XX`, `shotXX`, `scene_XX`, `sXX`, `XX_...`, إلخ.
2. **منع "سرقة" الصور بين المشاهد**:
   - منع المشهد رقم 24 من الاستيلاء على ملف `shot_02_ch171819_v24.png`، وضمان اقترانه بالمشهد رقم 2 حصراً.
3. **مطابقة مرنة لأسماء ملفات JSON**:
   - إذا كان اسم ملف الـ JSON هو `shot_02_ch171819_v26.png` والملف المرفوع هو `shot_02_ch171819_v24.png`، سيتعرف النظام الذكي على تطابق بادئة المشهد `shot_02` ويربطه كأولوية قصوى حتى مع اختلاف إصدار البرومبت (`v24` مقابل `v26`).
4. **تعبئة الفجوات التلقائية (Smart Gap Filler)**:
   - بعد الانتهاء من مطابقة الأرقام الصريحة، إذا بقيت مشاهد شاغرة (مثل المشاهد الـ 9 الشاغرة)، توفر الواجهة إمكانية ملء النواقص بالصور الفائضة تسلسلياً أو إشعار المستخدم بالمشاهد المفقودة بالاسم والرقم الدقيق.

## 2. User Experience & Visual Design

### تجربة المستخدم داخل نافذة المطابقة (Batch Image Matcher Modal)
- **شريط مؤشرات الحالة المحدّث**:
  - عرض إحصائيات المطابقة بوضوح: المشاهد المكتملة، المشاهد التي تم التعرف عليها برقم المشهد الصريح، وأي مشاهد مفقودة برقمها تحديداً (مثال: "المشاهد الناقصة: 40، 41، 42...").
- **زر إعادة المطابقة والفرز الذكي**:
  - زر بضغطة واحدة: "⚡ إعادة فرز ذكي حسب رقم المشهد (shot_XX)" لإصلاح أي مشروع حالي تم رفع صوره مسبقاً وتصحيح التداخل دون الحاجة لإعادة رفع الملفات من الصفر.
- **بطاقات المشاهد التفاعلية**:
  - تمييز لوني دقيق: أخضر للمشاهد المتطابقة تماماً، وأصفر هادئ للمشاهد الشاغرة مع زر رفع فردي أو سحب وإفلات مباشر.

---

## 3. Key Product Decisions & Trade-Offs

- **Decision 1: أولوية بادئة المشهد على الأرقام العشوائية داخل الاسم**:
  - *النهج المعتمد*: إعطاء الأولوية للنمط `shot_\d+` أو `scene_\d+`، واستبعاد أي أرقام مسبوقة بـ `v` أو `ver` أو `ch` أو `chapter` أو `ep` أو التواريخ.
  - *السبب*: جميع مولدات الصور ومصممي القصص المصورة يصدّرون الملفات بصيغ مثل `shot_05_ch12_v2.png`؛ رقم المشهد الحقيقي هو 5 وليس 12 أو 2.
- **Decision 2: حل الفجوات بدون تدمير الترتيب اليدوي**:
  - *النهج المعتمد*: لا يتم استبدال الصور التي تم تعيينها يدوياً (`manual`) إلا إذا طلب المستخدم إعادة الترتيب الشامل، مما يحفظ تخصيصات المستخدم.

## 4. Technical Architecture & Data Strategy

```
┌────────────────────────────────────────────────────────┐
│             Uploaded Image Batch Files                 │
│      (e.g., shot_02_ch171819_v24.png, ...)             │
└──────────────────────────┬─────────────────────────────┘
                           │
                           ▼
┌────────────────────────────────────────────────────────┐
│      extractPreciseShotNumber(fileName)                │
│  - Strip chapter info (ch171819)                       │
│  - Strip version tags (v24, v26)                       │
│  - Target explicit prefix: /^shot[_-]?(\d+)/i          │
│  - Result: shotNumber = 2                              │
└──────────────────────────┬─────────────────────────────┘
                           │
                           ▼
┌────────────────────────────────────────────────────────┐
│              Multi-Tier Matching Engine                │
│  Tier 1: Exact JSON filename match                     │
│  Tier 2: Normalized prefix match (shot_02 == shot_02)  │
│  Tier 3: Explicit shotNumber extracted match           │
│  Tier 4: Ordinal gap filler (for unmatched items)      │
└──────────────────────────┬─────────────────────────────┘
                           │
                           ▼
┌────────────────────────────────────────────────────────┐
│           Zustand Store (project.shots)                │
│  - customImageId linked                                │
│  - matchedFileName updated                             │
│  - imageMatchMethod = "shot_number"                    │
│  - 0 false steals, 100% accurate alignment             │
└────────────────────────────────────────────────────────┘
```
